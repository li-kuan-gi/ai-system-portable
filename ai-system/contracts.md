# 制度、知識與安全網契約

本檔定義 portable core 的上位責任模型。它不是日常任務入口；只有在制度設計、知識治理、安全網導入或跨層邊界不清時才需要讀。

## 核心目標

制度的目標是降低協作成本：

- 讓 agent 容易遵守，而不是要求 agent 記住大量例外。
- 讓使用者不必擔心 agent 亂衝、漏判、停錯或不做事。
- 讓高回頭成本處能停下對齊，低回頭成本處能自主推進。
- 不把無謂的審查、澄清與整理負擔轉嫁給使用者。

若一條規則讓 agent 更難正確行動，或讓使用者承擔更多低價值負擔，應視為制度設計問題，而不是只怪 agent 不遵守。

## 三責任模型

portable core 以三種責任分工，不以資料夾名稱本身作為邊界。

| 責任 | 角色 | 負責 | 不負責 |
|---|---|---|---|
| 制度 | 控制面 | 目標、判準、分工、停下 gate、變更規則 | 快速變動的事實、工具實作細節、命令級 permission table |
| 知識 | 事實面 | 已驗證事實、查證路徑、制度脈絡、安全網脈絡、知識系統脈絡、任務脈絡 | 取代制度判準、取代安全網攔截、保存 secrets |
| 安全網 | 執行面 | sandbox、hook、permission、approved scripts、機械式保護與驗證方式 | 判斷任務語意、保存 auth/session/cache、任意覆寫制度 |

制度不是把知識與安全網全文包含進來。制度只約定它們的目的、邊界、更新條件與信任方式。

## 制度契約

制度文件應回答：

1. 這個制度要降低哪一種協作成本。
2. agent 在一般任務中需要內化的最小判準是什麼。
3. 什麼情況應自主推進，什麼情況應停下對齊。
4. 哪些內容屬於知識或安全網，不應塞回日常規則。
5. 制度本身要如何被審計、修改與記錄。

制度的主要來源：

- `ai-system/rules.md`
- `ai-system/constraints-detail.md`
- `ai-system/governance/principles.md`
- `ai-system/governance/patchlog.md`

## 知識契約

知識是整個 portable system 的事實面，不只保存任務事實，也保存制度、安全網與知識系統本身的可查證脈絡。

知識系統應能處理四類脈絡：

- **制度知識**：制度為何這樣設計、哪些判準是正式來源、哪些是歷史或提案。例如「portable core 將責任分為制度、知識、安全網」。
- **安全網知識**：哪些保護是機械執行、哪些只是文字約束、實作如何驗證與更新。例如「以角色權限、hook 或 approved helper 分類實作安全網」。
- **知識系統知識**：知識如何被保存、查詢、索引、更新與淘汰。例如「以 RAG 實作知識查詢」、「哪些資料可進索引」、「查詢結果如何標示來源與查證程度」。
- **任務知識**：特定 domain、repo、API、環境、流程、業務語彙、常見錯誤與查證路徑。

知識可以描述制度與安全網，但不得取代制度判準或安全網攔截。知識不得把推測寫成事實；也不得保存 secret、token、password、cookie、bearer 或 credential 值。

## 安全網契約

安全網是把部分邊界交給機械式保護，而不是依賴 agent 臨場自制。

安全網實作一旦導入某個 instance，其結果不應隨使用者或 agent 的臨場意志任意更動。修改安全網應走明確流程：

1. 說明要降低的風險或成本。
2. 說明影響範圍與回復方式。
3. 優先 dry-run 或人工合併。
4. 不覆蓋 auth、session、cache、log、secret 或私有狀態。
5. 以 patchlog 或 adapter 自己的正式紀錄留下變更脈絡。

安全網核心契約見 `ai-system/safety-net/README.md`。具體 runtime 實作放在 `implementation-packs/` 或 instance adapter。

## 契約化檢查

新增任何制度、知識或安全網內容前，先回答：

1. 它負責什麼？
2. 它不負責什麼？
3. 正式來源在哪裡？
4. 誰可以改？
5. 什麼條件下能改？
6. agent 沒讀到細節時，仍應如何正確行動？
